# 前端质量自检清单（五支柱）

> 每个页面开发/改版完成后逐条打勾。**不通过不打勾，不交付。**
> 五支柱：用户旅程闭环 / 操作逻辑闭环 / 状态完备 / 布局层级 / 色彩语义。
> 前四支柱管「单页质量」，第五支柱管「模块级连贯与闭环」。

## 〇、用户旅程闭环（模块级，先于单页设计）

> **落地新模块/新功能前，先写用户旅程**：列出「从准备到收尾」的完整阶段
> （典型：准备 → 触发 → 执行 → 产物 → 沉淀反馈 → 度量），每阶段标注
> 对应页面/能力，再检查功能操作与内容展示是否完备严谨。**旅程有缺口，单页再美也是断的。**

- [ ] **旅程完整**：模块的六阶段（准备/触发/执行/产物/沉淀反馈/度量）都有落点，没有「做到一半没有出口」的断点
- [ ] **跨页连贯**：A 页的产出能自然流向 B 页消费（如「对话结论 → 保存知识库 → 检索复用」「巡检发现 → 转工单」），无死链、无孤儿入口
- [ ] **组合成能力块**：该模块所有页面合起来是一个完整能力闭环，而非互不相干的散页；入口/导航有唯一出处（共享导航数据源）
- [ ] **状态跨页延续**：关键上下文（选中的 Agent/模型/会话/过滤条件）在页面间跳转不丢失
- [ ] **入口可达**：每个能力的入口能从「它所属的业务流」走到（不是只能靠侧边栏硬找）
- [ ] **收尾有出口**：每个旅程以「产物或反馈」收尾（保存/下载/归档/点赞/生成报告），不让用户白干

## 一、操作逻辑闭环（断层与盲点根治）

- [ ] **前置校验**：操作按钮在条件不满足时禁用或给出原因（表单校验、依赖数据缺失、权限不足、状态机当前态不允许）
- [ ] **执行防重**：提交/执行中按钮 loading 并禁用，防双击重复提交
- [ ] **幂等与并发**：重复点击不产生重复数据（幂等 key）；多标签页同改一行有感知或保护
- [ ] **结果反馈**：成功有明确反馈（toast + 数据刷新 + 界面态迁移）；失败有错误提示且不静默
- [ ] **可恢复性**：危险操作（删除/覆盖/批量）二次确认；可撤销的尽量提供撤销；失败可重试
- [ ] **权限矩阵**：谁可见、谁可操作，与后端权限点一致（useCan 校验 + 无权限态）
- [ ] **后端异常映射**：401/403/404/500/网络超时各有对应 UI（跳登录/无权限/未找到/重试）

## 二、状态完备（不转圈、不白屏、不丢状态）

- [ ] **三态 + 兜底**：每个异步视图具备 loading / success / empty / error 四态；error 提供「重试」
- [ ] **空态设计**：列表为空有引导（说明 + 主操作），不是裸空白
- [ ] **深链兜底**：直接访问子路由（如 `/detail/:id`）时 id 不存在有「不存在或已删除」兜底，不死循环
- [ ] **刷新不丢**：刷新/返回后关键状态保留（store 持久化、URL 参数、localStorage）
- [ ] **数据一致性**：跨页面共享数据走 store，不各写各的；修改后相关视图同步刷新
- [ ] **加载边界**：骨架屏或 loading 态覆盖真实耗时；超长任务有进度或超时提示
- [ ] **真实联调**：用真后端跑一遍四态与异常，不用 mock 自欺

## 三、布局层级（合理与舒适）

- [ ] **一屏一主任务**：页面顶部 1 个主操作（高亮），其余降级（secondary/ghost）
- [ ] **4px 栅格**：间距/内边距只用 4/8/12/16/20/24 步进，不随手写奇数值
- [ ] **层级秩序**：导航 → 内容 → 操作区三段清晰；卡片内 header/body/footer 对齐
- [ ] **信息密度**：表格紧凑、说明稀疏；数据用表格、概念用卡片流图，不混用
- [ ] **主次分明**：标题 > 正文 > 辅助；危险操作（删除）放角落、红色、带确认
- [ ] **响应式底线**：窄屏不破版（表格横向滚动、表单单列、弹窗不超屏）

## 四、色彩语义（舒适与一致）

- [ ] **语义色三原则**：颜色只表意义（成功/警告/危险/信息），不表装饰；全站语义色 ≤5 个
- [ ] **变量驱动**：颜色全部走 CSS 变量（`globals.css`），深浅主题只换变量不动组件
- [ ] **对比度**：正文与背景 ≥4.5:1；浅色文字不落浅色底
- [ ] **国情语义**：涨红跌绿；告警红、健康绿；运维/金融语义尊重
- [ ] **节制**：主色只用于强调（按钮/选中/链接），大面积中性灰；宁少勿多

---

## 使用方式

1. **新模块**：先写用户旅程（§〇），确认六阶段闭环后，再按前四支柱做单页设计；
2. 新页面开发完成后按此清单逐项自检；
3. 不通过的项记入页面 PR 描述，说明原因或 TODO；
4. 季度性对高频模块（对话/工单/巡检）做一次旅程对照体检（对照页面清单 → 六阶段覆盖矩阵）。
