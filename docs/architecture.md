# OpsOrigin 架构说明

> 本文档描述 OpsOrigin 平台的顶层架构与设计约束，供架构评审、新人 onboarding 与跨团队对齐使用。各子系统的专题设计文档见 `docs/` 下对应文件。

## 1. 总体架构原则

### 1.1 写读分离、双库解耦

- **写（第一事实源）**：所有资产拓扑的元数据、模型定义、变更修改的第一落脚点锁定在 **PostgreSQL**。通过行级安全（RLS）和多租户标识保障数据隔离的绝对确定性。
- **读（高频拓扑计算）**：利用 **Dgraph** 图数据库承载三层级联拓扑的复杂查询、点对点寻路与环路检测。
- **最终一致性**：两库之间不发生显式双写。PostgreSQL 事务中内置 **Outbox（本地消息表）模式**，由独立旁路进程消费并异步、增量地刷入 Dgraph。

### 1.2 边缘跨域网络穿透控制

- 三层演进架构：`cmd/core`（中心）、`cmd/proxy`（隔离区代理）、`cmd/agent`（受控主机）。
- 中心与 Proxy 之间通过 **gRPC 双向多路复用流（Reverse Tunnel）** 异步维系。网络边界单向由边缘向中心发起连接，中心控制面不对边缘开放任何内网入向端口。

## 2. 技术栈

| 层 | 选型 |
| --- | --- |
| 后端 | Go（标准库 HTTP、gRPC、ent ORM） |
| 图存储 | Dgraph |
| 关系存储 | PostgreSQL |
| 前端 | Next.js（App Router）+ React + TypeScript |
| 组件 | FluxUI / 自建 UI 组件库 |
| AI | 大模型 Agent 框架（Streaming SSE、人在回路审批） |

## 3. 模块一览

- **CMDB**：模型管理、配置项实例、关系拓扑、采集策略。
- **监控中心**：监控插件注册、采集任务、指标与告警。
- **ITSM**：工单、流程引擎、服务目录、SLA/OLA、变更管理。
- **AI 中心**：数字员工（Agent）、技能市场、MCP 工具、提示词库、AI 工作空间。
- **知识库**：文章沉淀、收藏/关注、AI 伴写、自动沉淀策略。
- **报表中心**：数据集注册、看板、数据探索。

## 4. 安全红线（ASSERTIONS 摘要）

平台代码在静态扫描与运行期拦截器层面死锁以下核心红线（完整 10 条见历史评审记录）：

1. AI 涉及 High/Critical 影响范围必须挂起并转入人在回路审批。
2. AI 工具调用频受分布式令牌桶强约束，超阈值触发熔断降级。
3. 严禁硬编码告警与响应逻辑，统一转化为通用告警 Schema 经策略引擎路由。
4. 隔离区严禁对外部暴露网络端口，全量走反向隧道。
5. 目标机 Agent 保持无状态，禁止本地持久化 CMDB 元数据。
6. 异构多模存储严禁显式事务双写，必须走 Outbox。
7. 严禁高频数据跳跃，渠道置信度权重体系防止低权重覆盖高权重。
8. 严禁无凭证无 Trace ID 的匿名审计越权。
9. 严禁非多租户安全的裸 SQL / 裸图查询，底层强追加 `tenant_id`。
10. 拓扑关系层严禁未受检的无穷环路，建立连线前必须环路检测。
