# OpsOrigin 产品整体分析与同类产品对标

> 生成时间：2026-07-31 · 基于当前代码库实际能力盘点（非 PRD 承诺）

## 一、产品定位与全景

**OpsOrigin = AI-native 运维控制平面**。与传统运维平台"监控 + 工单 + 脚本"三层堆叠不同，它以 **AI 助手为指挥中枢**，Agent 为执行神经，打通 CMDB/ITSM/监控/脚本/知识库全链路。

### 当前能力全景（24 个后端模块 / 18 组前端页面）

| 能力域 | 模块 | 成熟度 |
|--------|------|--------|
| **AI 助手**（核心差异化） | ai（34 API） | ⭐⭐⭐⭐⭐ |
| **Agent 管理**（执行/采集/沙箱） | agentmgr（56 API） | ⭐⭐⭐⭐⭐ |
| **脚本自动化** | automation（脚本库/审批/版本） | ⭐⭐⭐⭐ |
| **工单/流程** | itsm（29 API） | ⭐⭐⭐ |
| **资产配置** | cmdb（29 API） | ⭐⭐（数据闭环薄弱） |
| **监控告警** | monitor（14 API） | ⭐⭐（被动采集缺失） |
| **发布部署** | deploy（17 API） | ⭐⭐⭐ |
| **通知/用户/权限** | notification/user/iam | ⭐⭐⭐ |
| **审计** | audit（3 API） | ⭐⭐（记录全，查询弱） |
| **漏洞/云** | vuln / cloud | ⭐（雏形） |

## 三、分模块差距分析

### 🔴 P0 — 可观测性断层（对标 Datadog/蓝鲸的最大差距）

> 📌 **已确认**：日志中心、链路追踪两项**暂不实施**，已写入 PRD §6 后续规划（用户决策 2026-07-31）。

| 差距 | 现状 | 处置 |
|------|------|------|
| **日志中心** | 无日志模块 | ⏸️ **暂缓（PRD §6.1）**：Agent collect 通道已具备，落地时可复用 |
| **链路追踪** | 无 | ⏸️ **暂缓（PRD §6.2）**：依赖日志中心落地后推进 |
| **指标只有主动探测** | probe + 内置指标 | 🔧 把 collect_metrics 落库数据**接入 monitor 图表**（内存模型改造为 DB 查询）—— 半程已完成，差最后一步 |
| **告警治理缺失** | 只有告警中心 | 🔧 按序补：第三方接入（Webhook）→ 收敛（去重/静默）→ 通知升级（钉钉/企微/邮件） |

### 🔴 P0 — CMDB 数据闭环（用户已识别的根因）

- 模型/关系/发现机制**整体薄弱**：impact/change-assess 仍用 MOCK，搜索无关系路径
- 对标 CloudExplorer/蓝鲸配置平台：**核心不在页面，在数据闭环**：
  1. 自动发现（Agent collect 模式已有雏形）→ 入库
  2. 关系推导（依赖/承载/包含）→ 拓扑
  3. 数据质量（去重/冲突消解/变更追溯）
- 建议：先做"发现 → 关系 → 追溯"闭环，再一次性补 impact/search 页面（而非逐页打补丁）

### 🟡 P1 — 平台化与集成（对标蓝鲸"集成平台"）

| 差距 | 现状 | 建议 |
|------|------|------|
| **Webhook 出站** | 无 | 事件总线 + Webhook（告警/工单/AI 审批结果推外部） |
| **SSO/LDAP** | user 10 API，需确认 | OIDC/LDAP 对接，企业落地刚需 |
| **多租户深度** | 有 tenant 维度 | 配额/隔离/审计细化 |
| **自定义工具调试** | MCP 注册了但无调试台 | 界面内试运行自定义 HTTP/CLI 工具 |
| **API 文档** | 无 OpenAPI 导出 | 生成 swagger，降低集成门槛 |

### 🟡 P1 — AI 体验与资产沉淀

| 差距 | 现状 | 建议 |
|------|------|------|
| 停止生成按钮 | 无（流式不可中断） | 加 AbortController 中断 |
| Markdown 渲染 | 自研轻量版 | 升级 react-markdown+GFM（表格/列表/任务） |
| 对话导出/模板库 | 无 | 导出 MD、Prompt 模板复用 |
| 审批策略 Agent 级入口 | 后端有，前端缺 | 补 Agent 级策略配置 UI |
| 知识库分类元数据 API | 缺 | category CRUD + 前端管理 |
| AI 成本可视化 | 有 token 记录 | 出面板：按 Agent/会话成本，配限额告警 |

### 🟡 P1 — 数据持久化一致性

| 位置 | 现状 | 建议 |
|------|------|------|
| monitor 指标 | 内存切片 | 迁 DB（collect_metrics 已就绪） |
| 告警历史 | 内存环形 200 条 | 落 PG（告警已确认/解决，历史价值高） |
| 采集任务调度 | PG 已落地 ✅ | — |

### 🟢 P2 — 差异化深化（保持 AI 领先）

1. **AIOps 根因分析**：告警 → AI 分析（已做）→ 升级为**告警关联聚类**（同源告警自动归并）+ 历史处置知识回灌
2. **自主模式强化**：执行计划先出后行（ask 确认 plan）、失败自动重试策略
3. **Agent 端能力**：Windows 支持面、bwrap 容器级隔离（此前讨论的方案）
4. **移动端/值班**：告警推送（APP/企微）+ 值班日历联动
5. **发布/变更闭环**：deploy 模块与 CMDB 关系联动（变更影响分析真数据）

## 四、优化路线图（建议优先级）

| 阶段 | 事项 | 预估 |
|------|------|------|
| **P0（先打地基）** | ① 监控指标接入图表（0.5d）② 告警通知渠道：钉钉/企微/邮件 Webhook（1d）③ CMDB 发现→关系闭环（2d）④ 审计查询增强（0.5d）⑤ AI 停止按钮+Markdown 升级（1d） | ~5d |
| **P1（补平台化）** | ① 事件总线+出站 Webhook（1.5d）② SSO/LDAP（1.5d）③ 审批策略 Agent 级 UI（0.5d）④ 自定义工具调试台（0.5d）⑤ 知识库分类管理（0.5d）⑥ AI 成本面板（1d） | ~5.5d |
| **P2（差异化）** | ① 告警聚类/收敛/升级（2d）② AI 执行计划确认流（1d）③ Agent 容器级隔离（2d）④ 告警推送+值班联动（1.5d）⑤ 发布-变更-影响联动（2d） | ~8.5d |
| **⏸️ 后续规划** | 日志中心（PRD §6.1）、链路追踪（PRD §6.2）—— 暂不实施，落地时重新评估 | 待定 |

**一句话结论**：OpsOrigin 的 AI 能力已经是"超纲"水准（对比所有同类），当前最该补的不是 AI，而是**可观测性地基（日志/被动指标）和 CMDB 数据闭环**——这两块补上后，AI 能调用的"真实数据"才完整，自主模式的价值才能最大化释放。
